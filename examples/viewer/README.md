# GLTS viewer

A reusable preview host for trusted `.glts` files. The application owns one
Three.js renderer, controls, viewport, and frame loop while each loaded root
contributes its native scene, optional default camera, and rendering profile.

Run it from the workspace root:

```sh
pnpm dev
```

Drop one self-contained `.glts` file anywhere on the page or choose it through
the file picker. GLTS executes as code and is not sandboxed, so only open files
you trust. A failed load leaves the current scene running.

## Bundled showcase

- `vintage-racecar/index.glts` — a 1950s front-engine grand prix car composed
  from five sibling `.glts` files through the contextual `gltsLoader`: the body
  shell, the chassis and exhaust, the cockpit, the preview paddock, and one wire
  wheel loaded as four instances.

The racecar was generated by Claude Opus 5 and then reviewed for GLTS
lifecycle, renderer ownership, and mobile cost. It uses no external assets.

## Replacement lifecycle

The viewer loads a candidate before replacing the current scene. On success it
calls `GLTSRenderer.release(scene)`, disposes the old GLTS scene, and revokes a
local object URL when needed. This lets every asset reuse the same WebGL context
while the application remains free to use or replace the authored default
camera.
